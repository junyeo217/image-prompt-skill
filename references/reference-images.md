# 참조 이미지의 역할과 속성 분리

이 문서는 사용자가 실제로 제공한 참조 이미지가 있거나 참조 기반 프롬프트를 요청했을 때만 읽는다. 파일 경로·이미지·현재 요청을 확인하지 못했다면 본 적이 있다고 가정하지 않는다.

## 먼저 참고할 느낌과 범위를 확인한다

`create`·`edit`에 사용할 참조 이미지를 받으면 실제 이미지를 보고, 사용자가 어떤 느낌·속성을 가져오려는지 현재 요청과 앞선 답변에서 확인한다. 범위가 불명확하면 참조를 반영한 프롬프트 작성·편집 전에 짧게 묻고 답을 기다린다. 관찰 가능한 색감·빛·명암·질감·정서적 분위기·구도 중 해당 이미지에 맞는 후보를 쉬운 말로 제시하며, 인물·의상·공간 자체의 재사용은 분위기 참고와 구분한다.

질문 예: “이 이미지에서 어떤 부분을 참고할까요? 색감과 빛, 질감과 분위기, 구도 중 원하는 부분을 말씀해 주세요. 조합하거나 다른 부분을 지정해도 됩니다.” 예시 항목을 고정 선택지로 강제하지 않고 실제 이미지와 요청에 맞춘다.

- 이미 “색감과 조명만”, “얼굴만”, “구도도 유지”처럼 범위를 지정했거나 같은 작업에서 앞서 답했다면 다시 묻지 않는다. 사용자가 선택을 명시적으로 맡긴 경우에는 참고할 속성을 짧게 밝히고 진행한다.
- “이런 느낌으로”만으로 전체 속성 복제를 가정하지 않는다. 여러 참조는 이미지별 미지정 범위를 한 번의 질문으로 모으고, 이미 정한 역할은 유지한다.
- 답변은 해당 작업의 참고·보존·변경 범위에만 반영한다. 지정하지 않은 인물·행동·장소·구도까지 자동 복제하거나 이후 다른 작업의 기본값으로 일반화하지 않는다.
- 이미지는 없거나 열리지 않으면 관찰했다고 가정하지 않는다. 단순 이미지 분석·평가 요청이나 `verbatim` 원문 전달에는 이 참조 선택 질문을 끼워 넣지 않는다. 편집 대상과 변경·보존 범위가 이미 명확한 부분 편집에도 새 분위기 선택을 요구하지 않는다.

## 참조마다 가져올 것과 바꿀 것을 나눈다

한 이미지를 얼굴·의상·소품·공간·카메라·조명의 모든 권위로 취급하지 않는다. 참조에서 가져올 속성과 현재 컷에서 바꿀 속성을 먼저 분리한다.

| 참조 역할 | 가져올 수 있는 속성 | 현재 요청이 우선하는 속성 |
|---|---|---|
| 인물·주체 | 얼굴의 식별 특징, 대략적 나이, 헤어, 체형 | 표정, 시선, 포즈, 행동, 감정, 크롭 |
| 의상 | 디자인, 원단, 색, 식별 디테일 | 착용 상태, 주름의 현재 방향, 포즈와 결합된 실루엣 |
| 소품 | 형태, 재질, 색, 식별 디테일 | 손에 드는 방식, 위치, 사용 행동, 크기 변화 |
| 공간·배경 | 공간 구조, 고정 요소, 서로의 상대 위치 | 시간대, 배치 변화, 현재 컷의 프레이밍과 깊이 |
| 카메라·축 | 인물과 공간의 앞뒤·좌우 관계, 시점의 기준 | 렌즈 결과, 거리, 크롭, 새 카메라 이동 |
| 조명·스타일 | 방향·색·표면 반응처럼 실제로 보이는 시각 속성 | 현재 요청의 시간·광원·대비·매체 지시 |

표의 기본은 시작점일 뿐이다. 사용자가 어떤 속성을 유지하라고 명시하면 그 속성을 보존하고, 바꾸라고 명시하면 현재 요청을 따른다. 참조에 없는 속성을 채우기 위해 팔레트·조명·질감·카메라를 발명하지 않는다.
보존 속성은 관찰된 범위에서 필요한 구체성(예: 기존 안쪽 의상·현재 색감)으로만 적고, 불확실한 품목명·시간대를 추정하거나 무관한 세부를 나열하지 않는다.

현재 `create`/`edit` 요청에서 관찰된 참조와 다른 시선·표정·프레이밍·샷 크기가 실제로 명시된 경우에만 그 차이를 구체화한다. 요청된 변경에 필요한 대상·관계만 화면 기준 왼쪽·오른쪽·위·아래로 적는 것을 기본으로 하고, 시선 관계가 필요하면 요청한 머리 방향과 눈동자 방향을 대상 위치에 대해 각각 설명한다. 닫힌 입은 입술 접촉처럼 보이는 상태로 적고, 고의적인 외면·곁눈질·머리와 눈의 불일치는 그대로 보존한다. 왼쪽 시선이나 닫힌 입을 기본값으로 넣지 않는다.
픽셀 좌표·바운딩 박스·해상도는 사용자가 명시적으로 요청·제공했거나 실제 측정 입력에 근거할 때만 쓰며, 요청값과 실측값을 구분하고 미확인 수치는 만들지 않는다. 이는 유용한 수치형 카메라 지시를 제한하지 않는다.

실사 공간에서 카메라를 바꾸라는 요청이 있을 때만 공간 안의 기준 위치·카메라 높이·피사체까지의 거리·촬영 방향으로 지시한다. 여기서 축은 인물과 공간의 좌우·앞뒤 관계이고, 카메라는 그 축을 보는 위치·높이·거리·방향이다. 단순 좌우 뒤집기는 실제 반대편 카메라의 원근·시차를 만들지 않으므로 반대편 카메라로 간주하지 않는다. 그 밖의 사진 요청에는 미터값이나 추가 질문을 강제하지 않는다.

샷 크기가 판단의 핵심일 때는 요청된 구도에서 보이는 피사체 점유, 주변 공간, 전경·후경 깊이를 서술한다. 보편적인 퍼센트는 쓰지 않으며, 미터·켈빈·`key:fill` 같은 수치는 프롬프트 조건이지 최종 픽셀에서 확인된 값이라고 보고하지 않는다.

## 여러 참조를 사용할 때

1. 각 참조를 한 번씩 실제로 확인하고, 어떤 속성을 제공하는지 짧게 기록한다.
2. 인물·의상·소품·공간처럼 역할이 겹치지 않도록 가져올 속성을 나눈다.
3. 현재 컷의 표정·시선·포즈·행동·카메라·크롭·조명·시간대가 참조의 보이는 자세와 다르면 현재 컷 지시를 우선한다. 그 속성까지 유지하라는 요청이 있을 때만 보존한다.
4. 여러 이미지의 충돌하는 속성은 조용히 합치지 않는다. 충돌하는 부분과 필요한 사용자 결정을 짧게 보고한다.

단순한 한 장 참조는 필요한 역할만 적으면 된다. 모든 역할 표를 강제로 채우거나 모든 참조 자료를 함께 읽게 하지 않는다. 참조 경로가 없거나 열리지 않으면 누락을 보고하고 임의 이미지·설명으로 대체하지 않는다.

## 참조 기반 작성과 편집

`create`에서는 참조에서 가져올 속성을 새 프롬프트의 관련 문장에만 반영하고, 나머지 장면·매체·구도는 요청과 기존 포맷 선택으로 결정한다. 참조 이미지가 있다는 이유로 포즈·카메라·조명·배경 배치를 일괄 복제하지 않는다.

`verbatim`에서는 참조 설명을 원문 안에 삽입하지 않는다. 원문 전달이 먼저이고, 참조 확인이 필요하면 원문과 분리된 보고에 적는다.

`edit`에서는 현재 편집 대상 이미지를 분명히 하고, 바꿀 속성과 보존할 속성을 함께 적는다. 색만 바꾸는 편집에 새 전체 팔레트나 조명을 넣지 않고, 노이즈 정리에 내용 삭제를 섞지 않는다. 현재 결과에서 실제로 확인한 범위를 넘어선 보정은 제안으로 분리한다.

사용자가 승인한 참조라는 상태명은 모델 지시문으로 복사하지 않는다. 참조가 제공하는 역할과 현재 컷에서 바꿀 속성을 자연어로 설명한다.

## 로드와 확인의 경계

이 문서는 참조 이미지가 있는 작업에서만 로드한다. 카테고리·타이포·화보·룩 자료는 요청에 맞는 기존 라우터 하나만 추가로 읽는다. 프롬프트 문장·검사기 결과·생성 기록은 실제 이미지 확인을 대신하지 않는다. 결과 파일이 생긴 뒤의 확인은 `result-review.md`로 넘긴다.
