# 이미지 프롬프트 작업 범위

이 문서는 `image-prompt`가 같은 이미지 요청을 서로 다른 작업 의도로 처리할 때의 최소 계약이다. 카테고리·홍보물·타이포 포스터·화보·룩의 선택은 `SKILL.md` 라우팅과 기존 참조를 그대로 따른다. 이 문서는 새 장르 기본값이나 새 포맷을 추가하지 않는다.

## 먼저 intent를 고른다

| intent | 사용 시점 | 작성 결과 |
|---|---|---|
| `create` | 사용자의 브리프에서 새 프롬프트를 만들 때 | 기존 C/P/TP·화보·룩 선택 흐름으로 빠진 결정을 채운 완성 프롬프트 |
| `verbatim` | 사용자가 완성 원문을 그대로 전달하거나, 별도 검사 문맥을 지정하지 않고 원문 검사를 요청할 때 | 입력 원문과 바이트 수준으로 같은 본문. 검사 결과는 별도 보고 |
| `edit` | 기존 프롬프트나 이미지를 요청 범위만 수정할 때 | 요청된 변경과 필요한 보존만 담은 부분 편집 지시 |

프롬프트를 작성해 달라는 요청은 생성 실행 승인을 포함하지 않는다. 명시적인 생성 요청은 상위 지침이 허용하는 범위에서 생성 권한이 될 수 있으며, 이미 승인한 동일 범위에 추가 재승인 루프를 요구하지 않는다. 생성 권한이 있는 경우에도 기존 native/imagegen 또는 `codex-imagegen` 호출 경로의 현재 계약과 상위 지침을 따른다.

검사 문맥과 본문 수정 권한은 구분한다. 예를 들어 “원문을 고치지 말고 create·A로 검사”라고 요청하면 본문은 그대로 두고 지정한 문맥으로 검사한다. 라벨이 없다는 사실은 의미가 없다는 확정 판정이 아니며 C1 의미 확인 대상으로 보고한다.

## `create`: 기존 공냥 패턴을 이용한 새 작성

1. 요청에서 카테고리·컷타입·피사체·구도·텍스트·AR를 확인하고, 기존 라우팅 표에서 C/P/TP·화보·룩 자료 중 필요한 것만 선택한다.
2. 포맷 A 또는 B를 고른다. A의 6섹션과 B 화보의 기존 슬롯 순서는 기존 작성 강점으로 유지하지만, 모든 매체에 새 슬롯 수를 강제하지 않는다.
3. 사진·포토리얼 매체에서만 사진적 수치와 피부 질감을 사용한다. 선화·플랫 벡터·단색·텍스트 중심 매체는 요청된 형태·배치·색을 우선하며 모공·필름 그레인·켈빈·key:fill을 자동으로 넣지 않는다.
4. 사용자가 주지 않은 세부는 기존 공냥 방식으로 보완하되, 상표·실존 인물·상위 안전 규칙을 넘지 않는다.

새 작성의 결과는 기존 출력 계약을 따른다. 단일 프롬프트는 설명 없이 본문과 끝의 `AR x:y`를 내고, 다중 결과는 기존 엔트리 구조를 유지한다.

## `verbatim`: 완성 원문 전달

`verbatim`에서 입력 본문은 전달 대상이다. 다음을 자동으로 하지 않는다.

- 언어 번역, 문장 추가·삭제, 문장 순서 변경, 맞춤법·구두점 교정
- `Scene:`·`Camera:` 같은 라벨, HEX, AR, 티어 문구, 안전 tail의 삽입
- 포맷 A/B에 맞추기 위한 줄바꿈·길이·슬롯 재작성
- 검사기를 통과시키기 위한 원문 변형

`verbatim`에서는 패턴·포맷을 선택하지 않고 참조를 로드하지 않는다.

원문이 검사 규칙과 맞지 않으면 원문은 그대로 두고 오류·경고·비적용을 별도 결과로 표시한다. 새 검사 모드의 `VERBATIM_PRESERVE`는 창작 양식 의무를 비적용으로 기록하는 사유이지 원문을 의미상 합격으로 바꾸는 신호가 아니다. 상위 안전 규칙이나 입력·경로 정합성 때문에 실행을 멈춰야 하는 경우에는 그 상태를 보고하고 원문을 몰래 고쳐 통과시키지 않는다.

## `edit`: 요청 범위만 수정

편집 지시는 다음 세 가지를 먼저 분리한다.

1. **대상:** 어느 프롬프트·참조 이미지·결과 파일의 어느 부분을 다루는지.
2. **변경:** 사용자가 실제로 바꿔 달라고 한 요소.
3. **보존:** 변경하지 말라고 했거나 현재 결과에서 유지해야 할 요소.

편집 본문에는 변경과 보존만 적는다. 사용자가 컵의 색만 바꿔 달라고 했다면 컵의 색과 그 결과를 읽는 데 필요한 국소 관계만 다루고, 새 전체 팔레트·새 조명 설계·새 장면·새 질감을 추가하지 않는다. 팔레트나 조명을 바꾸는 요청이면 해당 변경만 명시하며, 요청하지 않은 색상 체계나 조명비를 발명하지 않는다.

정리·단순화 편집은 내용량을 줄이는 작업과 질감 노이즈를 줄이는 작업을 구분한다. 명시된 정리 범위 안에서 작은 점 노이즈·과한 미세 대비·복잡한 미세 음영을 줄일 수 있지만, 장면의 정체성·구도·포즈·환경 밀도·재질 정보를 임의로 삭제하지 않는다. 원본에서 실제로 확인하지 못한 속성을 보충해 쓰지 않는다.

## 매체 조건과 검사 문맥

검사기 새 모드의 호출 문맥은 다음 세 옵션으로만 전달한다.

```text
--intent create|verbatim|edit
--format A|B
--medium-limits <CSV>
```

`--medium-limits`의 허용 토큰은 `camera`, `lighting`, `photo-texture`, `palette-count` 네 가지다. CSV에는 이 토큰의 쉼표 구분 목록만 넣으며 다른 값·철자·프로젝트 용어는 오류다. 플래그가 전혀 없으면 기존 검사 동작을 사용한다. `--intent` 또는 `--format`을 명시하면 새 검사 모드로 판정한다.

매체 제한은 다음 사진적 의무만 비적용으로 기록할 수 있다.

- `camera`: 사진적 카메라·렌즈 결과 토큰
- `lighting`: 사진적 조명·색온도·key:fill 토큰
- `photo-texture`: 피부·필름 그레인 등 사진 표면 토큰
- `palette-count`: 사진 팔레트의 고정 HEX 개수 의무

이 제한은 레이아웃·배치 의미, 요청된 매체가 무엇인지, 사용자가 지정한 색상이 반영됐는지 확인하는 일을 면제하지 않는다. 비적용 결과는 `skipped:[{code,reason}]`으로 남기며 `MEDIUM_LIMIT`, `VERBATIM_PRESERVE`, `EDIT_SCOPE`를 섞어 쓰지 않는다. C1의 라벨 없는 내용 키워드가 실제 의미를 보장하지 못하면 `W-SEMANTIC-REVIEW`를 내고 에이전트가 해당 의미를 확인한 결과를 별도로 기록한다. 이는 기계적 PASS로 바꾸지 않으며 기존 상위 사용자 승인과 별개다.

이 문맥은 검사기 호출 옵션에만 둔다. `skipped`는 검사 결과의 설명이며 JSONL 레코드 필드가 아니다. 기존 JSONL의 레코드 필드·실행기 입력·배치 스키마를 추가하거나 재해석하지 않는다. 입력 존재·경로·원문 보존 판정은 스타일 양식 검사보다 우선한다. 보편 8슬롯·매체 사전·장르별 조명 defaults·새 runtime·승인 훅은 만들지 않는다.

## 로드 범위

이 문서는 모든 요청에서 자동으로 읽는 자료가 아니다. 일반 `create`는 기존 카테고리·포스터·화보·룩 자료 하나를 선택하고, intent 구분·부분 편집·정리 판단이 필요할 때만 이 문서를 읽는다. 참조 이미지가 실제로 제공된 경우에만 `reference-images.md`, 결과 파일을 실제로 확인하는 경우에만 `result-review.md`를 추가로 읽는다. 한 장의 사진을 다루는 작업에도 사용되지 않는 자료를 일괄 로드하지 않는다.
