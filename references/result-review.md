# 생성 결과 확인과 전달

이 문서는 실제 이미지 결과나 결과 파일을 확인할 때만 읽는다. 프롬프트를 읽었거나 작업이 대기열에 들어갔다는 사실은 렌더 결과 확인이 아니다.

## 확인 순서

1. **프롬프트·검사기 상태:** 오류·경고·`skipped`를 읽는다. `ok`는 문법·규칙 판정이며 렌더 품질이나 사용자 승인이 아니다.
2. **파일 상태:** 실제 경로에 파일이 있고 열리는지, 포맷·픽셀 크기·파일 크기가 요청과 맞는지 확인한다. 경로가 없으면 성공으로 기록하지 않는다.
3. **실물 표면:** 사용 가능한 이미지 뷰어·렌더 표면에서 실제 이미지 파일을 열어 요청된 구도·주체·참조 속성·매체·조명·색·질감·텍스트 읽힘을 확인한다. PNG 정본과 WebP 파생본이 모두 있으면 각각 확인한다.
4. **요청 상태:** `create`는 브리프 충족, `verbatim`은 원문 전달, `edit`은 요청 변경과 보존 범위를 각각 판정한다. 사용자 승인 상태는 별도로 남긴다.

## 관계와 판정 분리

장면 관계가 요청된 결과에서는 실제 이미지에서 대상의 위치를 먼저 찾고, 얼굴·머리 방향과 눈·동공 방향을 따로 확인한다. 하나만 맞아도 관계가 맞다고 선언하지 않는다. 보고에는 미감상 성공, 장면 요구 충족·실패, 사용자 수용을 별도 상태로 남기며, 요청된 속성만 검사한다.

## intent별 판정

### `create`

라우팅된 C/P/TP·화보·룩 선택과 요청 매체가 결과에 반영됐는지 본다. 선화·플랫 벡터·단색 결과에 사진적 피부·필름·조명을 새로 넣었는지, 사진 작업에 필요한 실제 색·조명·재질이 빠졌는지를 구분한다. 한 번의 검사 통과만으로 시각 결과를 합격시키지 않는다.

### `verbatim`

전달된 프롬프트 본문이 원문과 같은지 별도로 비교한다. 검사기가 오류나 경고를 내더라도 번역·문장 추가·라벨·HEX·AR를 넣어 고치지 않는다. 원문 보존 판정과 결과 이미지의 품질 판정은 서로 다른 기록이다.

### `edit`

사용자가 요청한 변경이 실제로 일어났는지, 지정한 보존 요소가 유지됐는지 본다. 요청하지 않은 장면·팔레트·조명·질감 변경이 생기면 범위 이탈이다. 사용자가 현재 프레임·룩을 선호하고 결함이 국소적이면 성공한 빛·팔레트·구도를 다시 쓰지 말고 결함 위치·변경 범위·보존 항목으로 범위가 한정된 편집 의도를 남긴다. 사용자가 새 프레이밍·장면을 명시하면 그 변경은 반영하되, 사용자가 선택한 `create`/`edit` intent의 범위와 권한을 따른다. 새 샷이라는 이유만으로 `create`로 바꾸지 않으며, `edit` 선택은 추가 생성·크롭·자산 생성 같은 새 부작용 권한을 부여하지 않는다.
작은 결함은 결함에 맞는 최소 수정으로 기록하고, 반복 편집이 결과를 악화시키면 이전 결과를 보존한 채 확인된 제약에서 대안을 선택해 이미 부여된 권한 범위 안에서 실행한다.

정리 편집은 내용 삭제와 표면 정리를 구분한다. 점 노이즈·과한 미세 대비·복잡한 미세 음영만 줄이도록 요청된 경우 인물·소품·배경 밀도·재질의 정보량을 유지한다. "깨끗해졌다"는 인상만으로 배경이나 생활 흔적을 지운 것을 합격시키지 않는다.

## PNG 정본과 WebP 파생본

이미지 결과의 정본은 PNG로 보존한다. 사용자가 WebP를 명시적으로 요청한 경우에는 먼저 현재 설치된 기존 변환 수단을 확인하고, 확인된 경로로만 별도 파생본을 만든다. `cwebp`를 가정하지 않으며, 사용할 수단이 없으면 임의 설치나 새 변환 코드 없이 WebP 변환 미실시·미완료로 보고하고 PNG 정본을 보존한다. 확장자만 바꾸는 것은 변환이 아니다. WebP 파생을 위해 새 인코더·변환기 코드·runtime을 추가하지 않는다.

WebP를 요청하지 않았다면 WebP 파생본을 만들지 않는다. 변환 실패와 렌더 실패를 별도로 기록하고, 변환 실패를 이미지 재생성의 근거로 바꾸지 않는다.

## 보고 경계

실제 결과를 열어 보지 못했으면 "시각 확인 미실시"로 남긴다. 검사기 통과·파일 생성·대기열 상태·생성 기록만으로 구도, 연속성, 텍스트 판독, 품질, 사용자 승인을 주장하지 않는다. 프롬프트 작성과 실제 생성·다운로드·외부 게시는 각각 별도 권한과 상태로 다룬다.

결과 확인 보고서는 요청·참조·변경 범위에 필요한 관찰만 담는다. 프로젝트 전용 승인 체크리스트나 상태 토큰을 범용 문서에 복사하지 않는다.
